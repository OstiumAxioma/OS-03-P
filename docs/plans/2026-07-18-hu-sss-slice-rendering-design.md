# HU 组织切片 SSS 渲染设计

## 目标与坐标约定

每张医学切片使用一个无圆角、封闭的薄盒子，不再使用圆角玻璃主体、内部黑底 Plane、四条独立边框和额外描边。场景统一采用 Z-up：X 表示左右，Y 表示切片层深和排列方向，Z 表示上下。相机 `up` 设置为 `(0, 0, 1)`；激活切片保留 X 方向偏移和小幅正弦波动，同时主要沿世界坐标 Z+ 抽出。右下角坐标轴使用相同相机方向，因此上方明确显示 Z+。

## 影像数据与组织映射

服务器继续通过 ITK-Wasm 解码影像，并在生成最多 7 张切片时输出三张逐像素纹理：RGBA 组织颜色、单通道粗糙度和单通道 SSS 厚度。CT 使用连续 HU 传递函数：空气为完全透明；肺、脂肪、软组织、致密组织和骨分别使用低饱和的人体组织色，并在区间边界间插值，避免明显色带。空气像素的 RGB 可以为黑色，但 alpha 必须为 0，因此不会显示黑底。非 CT NIfTI 不宣称 HU 语义，按体数据范围归一化后使用同一视觉调色板，并在响应和界面标记为 `normalized`。

## GPU 材质结构

前端切换到 `WebGPURenderer`，设备不支持 WebGPU 时使用 Three.js 自带 WebGL2 后端。每层只有一个 `BoxGeometry` Mesh；盒子的正反面共享 `MeshSSSNodeMaterial`，侧面共享物理边缘材质。组织 RGBA 同时驱动表面颜色与空气遮罩，厚度纹理驱动 `thicknessColorNode` 和 `thicknessAttenuationNode`。使用 `RoomEnvironment + PMREM` 提供 PBR 环境照明，同时保持页面背景为 `#53ffba`。不再使用透明度小于 1 的 transmission 混合来伪造组织；空气通过 alpha 丢弃，组织通过 PBR 直接光照和 SSS 获得透光感。

## 验证边界

单元测试覆盖 HU 关键点、空气透明、连续插值、NIfTI 归一化、纹理长度、Z-up 布局和 Z+ 抽出。生产构建用于验证 Three.js WebGPU/TSL 打包；真实浏览器验证 WebGPU 或 WebGL2 回退、无黑底、盒子轮廓、Z+ 方向和悬停动画。该颜色映射只用于可视化效果，不作为医学诊断分割或组织定量结论。
